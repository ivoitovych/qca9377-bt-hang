## 1. The defect, at master `82667d713949`

| step | where |
|---|---|
| `a2dp_reconfig()` takes a setup (`a2dp_setup_get()`, a new one with ref 1 when none exists), adds its callback | `profiles/audio/a2dp.c:2110-2137` |
| `avdtp_close()` refuses: "rejecting since close is already initiated" | `a2dp.c:2162`; `avdtp.c:3732-3735` |
| `avdtp_abort()` sets ABORTING and, the Close being the pending request, calls `cancel_request(session, ECANCELED)` | `a2dp.c:2164`; `avdtp.c:3788-3791` |
| `cancel_request()` → `close_cfm()` with an error | `avdtp.c:2624-2632`; `a2dp.c:1675-1696` |
| `finalize_config()` → `reconfig_cb()` (the D-Bus error reply) → `setup_cb_free()` → `setup_unref()` → `setup_free()` | `a2dp.c:410-430`, `333-343`, `300-310`, `277-298` |
| back in `a2dp_reconfig()`: `setup->reconfigure = TRUE;` on the freed setup | `a2dp.c:2173` |

The same chain has a second ending: if `cancel_request()` cannot send the Abort it returns the
error, `avdtp_abort()` returns it, and `a2dp_reconfig()` goes to `fail:`, which calls
`setup_cb_free(cb_data)` on the callback `finalize_config()` already freed, and `set_configuration()`
then replies to the D-Bus call a second time (`a2dp.c:2166-2169`, `2190-2192`, `2233-2238`;
`avdtp.c:2656-2668`).

Introduced by `5071fadb97b8` ("a2dp: Try aborting when switching endpoints", 2019-05-03, first in
5.51): before it `a2dp_reconfig()` called only `avdtp_close()`, which completes nothing
synchronously. Every release since, Ubuntu 24.04's 5.72 included, has it.

Upstream: no fix and no report. `scripts/patchwork-recent.py 2026-08-01 'a2dp|avdtp|reconfig|setconf|use.after.free|uaf'`:
56 subjects, none on `a2dp_reconfig()` (Jinwang Li's pending 14893870 changes `connection_lost()`'s
order, a different path). The cached lore archive (2026-09-10 to 2026-10-29, 2500 messages):
`git log -S a2dp_reconfig --all` finds nothing.

## 2. The fix (`069fcf2d5`)

`a2dp_reconfig()` holds a reference to the setup across `avdtp_close()`/`avdtp_abort()` (the
pattern of `a2dp_cancel()`), sets `reconfigure` and drops it. If `avdtp_abort()` fails, the request
is freed and the error returned only if its callback is still on the setup (looked up by the
callback's id); otherwise it was completed and replied to already, and 0 is returned.

Why this and not the alternatives:
- **Setting `reconfigure` before the calls** (as `a2dp_config()` does at `a2dp.c:3354`, `3384`)
  removes the write after the free but not the second ending above: a failed Abort send still
  frees the callback twice and replies twice.
- **Keeping `reconfigure` set when the request was completed synchronously** is what the code did
  before for a setup that survives (one shared with another pending request): `abort_cfm()` drops a
  reference whenever `reconfigure` is not set (`a2dp.c:1744-1748`), a reference this path never
  handed it, so clearing the flag would unbalance the count.
- **Adding the callback only after the calls** would change which request the canceled Close
  completes; larger, and the reply would then depend on the Abort's outcome.
