# CO-38 and CO-44 on bluetooth-next and every stable line CO-38's `Cc: stable` reaches (2026-11-23)

The operator's rule (2026-11-23): a `Cc: stable` goes on a patch only once it is shown to work on
the stable lines, at least in a VM, with the testers run on each. This file is that run. CO-44,
whose package carries no stable tag, was run on the same kernels: one patched image per line
holds both one-line fixes.

**Notes.**
- **7.3.5 stops at the SCI cases.** 7.3.5 alone stops at "Set Low Energy on 6.2 - SCI Setting"
  (timed out; the rest are not run), the same on base and patched. That is BT-15: 7.3.5 lacks
  `5874f8d03268`, which the stable team has queued for 7.3. So 7.3 was rebuilt with that commit
  (`evidence/scripts/build-73sci.sh`) for the full run.
- **One timeout in 7.3 + SCI.** In the first patched full run, "Pairing Acceptor - SMP over BR/EDR
  2" timed out; it passed on base. It then passed 10 of 10 alone on each kernel
  (`evidence/scripts/rerun-case.sh`), and in two more patched full runs. Those two runs gave 514
  passed and 16 failed, the same 16 as base without the two new cases. It counts as a one-off,
  not a change.
- **6.1.192 has a lockdep warning** ("possible circular locking dependency": `hdev->lock` taken in
  `discov_off()` from the `discov_off` work) on base and patched alike. It is that line's own and
  appears on none of the others.
- **mesh-tester's 2 failures on the stable lines** are on base and patched alike. On
  bluetooth-next both pass.
