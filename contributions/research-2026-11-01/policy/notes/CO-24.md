## 2. The answer, from source (no device needed)

Three paths lead into hands-free on a fresh device. All three pick the best codec the
headset and adapter support.

1. WirePlumber 0.4.17 automatic switch (a recording stream):
   [source] `src/scripts/policy-bluetooth.lua` at tag `0.4.17`: `switchProfile()` l.216;
   with no `saved-headset-profile:<device>` (l.239-243) it calls
   `highestPrioProfileWithInputRoute()` (l.244-246, defined l.164-199): the
   highest-priority profile listed by any input route.
   [source] PipeWire 1.0.5 profile priorities, `spa/plugins/bluez5/bluez5-device.c`:
   `headset-head-unit` 1 (l.1790), the codec profiles `1 + hfp_codec` (l.1787, "prefer msbc
   over cvsd"): CVSD 2, mSBC 3. The input route lists all three (U4 entry, [log]:
   `profiles` [3, 260, 261]). So mSBC, if the headset and adapter support it.
2. GNOME Settings, choosing the "Handsfree - <headset>" output while in A2DP:
   [source] libgnome-volume-control `91f3f414`, `gvc-mixer-control.c:610-614`: no stream for
   that output, so `gvc_mixer_control_change_profile_on_selected_device(..., NULL)`;
   `gvc-mixer-ui-device.c:538-550`: the candidate with the highest priority. PipeWire's pulse
   layer passes the profile priority through (`collect.c:170` at `1.0.5`). So mSBC again
   [inferred: the panel's candidate list was not captured].
3. The plain `headset-head-unit` entry (U1): PipeWire as audio gateway sends `+BCS: 2`
   (mSBC) at connection when the headset supports codec negotiation and mSBC
   (`backend-native.c:870-873` at `1.0.5`); the plain entry carries no codec of its own
   (`set_profile()`, `bluez5-device.c:1208` only switches for a codec profile).

[source] WirePlumber master `4ab992fa2931` (0.5.19), `src/scripts/device/autoswitch-bluetooth-profile.lua`:
the same rule (`highestPrioHeadsetProfile()` l.109; used at l.189 when no valid saved
profile exists), plus a check that a saved profile really is a headset profile (l.180-186).
PipeWire master ranks HFP codec profiles by codec order (`bluez5-device.c:2450`,
`1 + supported_codec_count - prio`), so the best codec (LC3-SWB where supported, then mSBC)
wins.

## 4. Recommendation material

- The open question is answered from source: no saved choice gives the best supported codec
  (mSBC on this stack). Nothing to report; no fresh device and no deletion of saved state
  are needed.
- Optional confirmation, free: the next time any new headset is paired, look for its first
  `Setting profile of '<name>' from: a2dp-sink to: headset-head-unit-…` in the user journal.
