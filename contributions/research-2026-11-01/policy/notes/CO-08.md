## 3. PipeWire, upstream (master `4cfc471123a0`, 2026-10-30) against 1.0.5

- [source] SBC-XQ is not chosen automatically. Codec order puts SBC before SBC-XQ
  (`spa/plugins/bluez5/codec-loader.c:41-42` at `1.0.5`), and A2DP profile priority follows
  that order (`bluez5-device.c:1668` at `1.0.5`). It is reached only by a user choice, which
  WirePlumber then saves and restores (as at 01:40:14 above, and in `EX-030`, 08-17).
- [source] SBC-XQ's configuration, unchanged 1.0.5 to master: prefers Dual Channel
  (`a2dp-codec-sbc.c:128` and `:246` at `1.0.5`; `:130`, `:249` at master); bitpool 39 per
  channel at 48 kHz (`:92` at `1.0.5`, `:94` at master), 2x39 = "512 kbps" class per the
  comment there; plain SBC joint stereo 58 capped by the speaker's 53.
- [source] No setting selects SBC channel mode or bitpool: `codec_select_config()` takes a
  `settings` dict and never reads it (`a2dp-codec-sbc.c:136` at `1.0.5`, `:138` at master).
  So the dossier's step 2 (Dual 26 vs Stereo 52 vs Dual 39) needs a rebuilt SBC codec plugin.
- [source] Commits on `a2dp-codec-sbc.c` since 1.0.5 (`git log 1.0.5..origin/master`): none
  changes SBC-XQ's choice. `45385b2b6` (SBC-XQ shares the SBC endpoint) and `a6f529b50`
  (companion-codec caps) touch endpoint registration only.
- [source] Reviewer 2's "inverted bitpool range": `conf.min_bitpool = MAX(2, remote min)`,
  `conf.max_bitpool = MIN(default, remote max)` (master `:208-209`) has no min<=max check. It
  cannot fire for the T8 (remote min 2). Unrelated to U10.
- [source] Quirk database, master `spa/plugins/bluez5/bluez-hardware.conf`: `sbc-xq` is
  disabled for Motorola DC800/S305 (l.41-42, #1590), "PMK True Wireless Earbuds" (l.43,
  `d26916828`), "SoundCore 2" (l.49, #2291), and by address prefix for Phonak (l.56,
  `34bca4a00`, #3939). No Tronsmart entry.

## 4. The test (the operator's, about 10 minutes)

Purpose: one marked yes/no per mode and per channel, so the quirk rests on a marked test, as
the project's rules ask, not on the 10-11 recollection.

Before (operator):
1. The T8 on and connected; GNOME Settings, Sound, Output = the T8; nothing else playing
   (Chrome closed or paused: its playback reached the link as encoded silence on 10-11).
2. The HCI trace is being written: `ls -lt /var/log/bt-health/trace` shows a file modified
   in the last minute.
3. Leave the output volume slider where it is for the whole test; write its value in the
   first mark.

Marks: `logger -t bt-mark -p user.notice "U10 <text>"`. Same identifier as `bt-mark`, but
no `bluetoothctl` call (BT-4: a MGMT open can abort the capture's btmon) and no controller
probe (the installed `bt-mark` sends HCI Read Local Name).

Sounds:
- S1: Settings, Test, "Front Left", then "Front Right" (as on 10-11).
- S2: both channels at once: `pw-play /usr/share/sounds/alsa/Front_Center.wav` (mono,
  48 kHz, 1.43 s; PipeWire should copy it to both channels [inferred]; the per-channel
  script shows afterwards whether it did).

Sequence, A-B-A-B so speaker state and drift cannot explain a difference:
| step | Configuration (Settings) | play | mark |
|---|---|---|---|
| 0 | — | — | `U10 start, slider <n>%, T8 volume unchanged` |
| 1 | SBC | S1 left, S1 right, S2 | `U10 SBC run1: left yes/no, right yes/no, both yes/no` |
| 2 | SBC-XQ | same | `U10 XQ run1: left ..., right ..., both ...` |
| 3 | SBC | same | `U10 SBC run2: ...` |
| 4 | SBC-XQ | same | `U10 XQ run2: ...` |
| 5 | SBC (leave it there) | — | `U10 end` |

Wait about 3 s after each switch before playing (the switch takes about 0.6 s). "Partial"
(quiet, distorted, one side) is a valid answer; write it.

Afterwards (no operator time): the window from the marks; `sbc-channel-levels.py` per
second over it (signal per channel and mode); `capture-window.sh` for Set Configuration and
AVRCP volume at each switch; the marks from `journalctl -t bt-mark`.

Reading:
- SBC-XQ silent on S1 and S2 in both runs, SBC audible in both: the quirk case, exactly the
  #2291/#1590 pattern. The entry is `no-features = [ sbc-xq ]` for the T8.
- SBC-XQ plays one side only: still SBC-XQ-specific (the #5545 class); same entry.
- SBC-XQ audible: U10 is withdrawn; drop CO-08 and correct the record.
- Mixed between runs: repeat once; if still mixed, drop.

Cost: 10 minutes of the operator's time with the speaker, A2DP only (no SCO, no controller
command beyond normal AVDTP). No install, no restart.

Then, before any entry: the T8's `Modalias` (vendor/product id) for a match rule that does
not depend on the name (the maintainers' preference in #3939). It is in `bluetoothctl info`
or BlueZ's device `info` file; not read here (task scope).

Local relief, the operator's choice and independent of upstream: choose SBC again (saved and
restored from then on), or a user override of the hardware database with the T8 entry.
