## 3. The backport

    diffstat work/hunks.diff
     bluez5-device.c | 71 +++++++++++++++++++++++++++++++++-----------------------
     1 file changed, 42 insertions(+), 29 deletions(-)

What it does (all in `spa/plugins/bluez5/bluez5-device.c`):
- `build_profile()`, HSP_HFP: codec 0 -> no profile (the codec-less line is gone);
  CVSD is always listed (the native backend answers -ENOTSUP for every codec on
  an HSP-only device, `backend_native_supports_codec`), mSBC only if supported;
  the best supported codec gets the base name `headset-head-unit`, the others
  `-cvsd`, as A2DP already does.
- `get_index_from_profile()`: HSP_HFP with codec 0 -> SPA_ID_INVALID.
- `emit_nodes()`: the HFP codec comes from the existing transport (no codec
  filter on the lookup), default CVSD, so the current profile is always a listed one.
- `profiles_changed()`: the reset of the codec to 0 is removed.
Left out from upstream: the A2DP/BAP lookup simplification, `DEVICE_PROFILE_LAST`
change, `codec_switched` fallback rewrite, the `set_profile` HFP_AG condition
(not needed for this behaviour; kept as in 1.0.5).

Differences to the upstream commit, to be reviewed: (a) `emit_nodes()` resets
`props.codec` only in the HSP_HFP case; (b) `codec_switched()` failure branch
unchanged (harmless: `emit_nodes()` recomputes the codec); (c) CVSD exemption
and mSBC top codec (no LC3-SWB in 1.0.5).
