# EX-012 — probe-clustering-was-reverse-causation

**Claim.** An apparent observer effect — 6 of 8 HCI timeouts falling in the first 10% of their liveness-probe gap — was produced by **outcome-dependent interval construction**. Some timestamps defining the exposure intervals were generated by the controller's own failure behaviour. Once only exogenous boundaries remained, the evidence was too sparse to test the corrected null.

**⚠️ What is NOT claimed.** That the corrected analysis demonstrates independence. It does not, and cannot: after the correction only one event remained placeable, and one phase establishes nothing. The precise statement is *the apparently dramatic evidence for an observer effect disappeared*, leaving data insufficient to establish one either way. An earlier version of this exhibit said "the clustering disappears completely", which reads as a positive finding of independence and overstates it.

**Post-review statistical correction.** The captured output below says mean phase 0.5 is
expected “under independence.” That wording is too strong and is preserved only because the
output is verbatim. Uniform phase additionally requires an approximately constant failure
hazard within the probe intervals. `bt-phase` now states that null explicitly.

**Terminology.** "Reverse causation" is the loose description; the precise one is **outcome-dependent sampling** — the controller's behaviour generated some of the timestamps that were then treated as an independent exposure clock. Once that happens the statistic can be mathematically perfect and epistemically meaningless.

**Relevance.** A near-miss worth recording. The statistic was computed correctly and the tool's warning fired exactly as designed; the INPUT was invalid, because the probe is not independent of the event under study. A udev rule fires the health probe on bluetooth and USB add/remove — precisely the events a failing controller generates — so probes cluster around incidents because the incident causes them. The tell was in the gap lengths: 2.7 s, 6.8 s, 9.2 s, where a 15-minute timer cannot produce a 2.7-second gap. General rule: an exposure denominator must be built only from events that could not have been caused by the thing being measured.

## Extraction method

Re-runnable as-is on the affected machine:

```console
$ echo 'timer cadence (the only exogenous probe source):'; systemctl cat bt-health-snapshot.timer | grep -E 'OnUnitActiveSec|OnBootSec'; echo; echo 'udev rule — fires the SAME probe on controller failure events:'; grep -v '^#' /etc/udev/rules.d/51-bluetooth-health-snapshot.rules | grep -E 'ACTION' ; echo; echo 'exogenous-only analysis of a boot that hung:'; bt-phase -b -2 2>/dev/null | tail -14
```
