Bluetooth: MGMT: remove the mesh advertising instance when done

mesh_send_done_sync() only disables advertising when hdev->adv_instances
is empty, but the instance a mesh packet is advertised through
(le_num_of_adv_sets + 1) is itself on that list and nothing removes it,
so for a mesh transmission the check is never true and advertising is
never disabled here. On the legacy advertising path the controller
keeps advertising the packet and the stale instance stays scheduled for
1000 seconds (hci_schedule_adv_instance_sync() arms adv_instance_expire
with adv->remaining_time, the 1000 the instance was added with); with
extended advertising the set stays enabled until the duration the
controller was given ends. Before the list check was added the disable
was unconditional, which is what the tools/mesh-tester cases
"Mesh - Send cancel - 1/2" have expected since 2022 and now time out on.

Tear the instance down the way Remove Advertising does, with
hci_remove_advertising_sync(): on the legacy path this drops the
instance, cancels its timer and reschedules the next instance if there
is one; with extended advertising it disables and removes that set
only, so other advertising sets keep running, which is what the list
check was added for. The existing list_empty() check then disables
advertising only when no other instance is left.

All removal paths end in mgmt_advertising_removed(). The mesh instance
is internal - Add Advertising rejects instances above
le_num_of_adv_sets, Read Advertising Features hides them and no
Advertising Added is ever sent for them - so skip the event for it
instead of announcing to userspace the removal of an instance it never
saw.
